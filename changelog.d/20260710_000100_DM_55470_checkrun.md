### Other changes

- The GitHub check-run notebook-execution failure reporting now derives its annotation titles and messages from the shared execution-outcome formatter (`timessquare.domain.executionoutcome`) rather than hand-branching on Noteburst error codes. This removes duplicated failure-description logic so the check-run annotations and the API `execution_error` field cannot drift apart. Annotations for execution timeouts, Jupyter errors, and unexpected system errors are unchanged, but two cases now read differently: when Noteburst's stored result has expired, the annotation is now "Notebook result unavailable" with a prompt to re-run the notebook (previously an uninformative title and a message that printed a literal `{job_result.status}` placeholder), and the fallback for an unrecognized Noteburst error is now "The notebook execution failed for an unknown reason." (previously "The noteburst error is unknown."). Additionally, a Noteburst response that claims success without returning an executed notebook now raises an error that surfaces in the worker logs, instead of being silently ignored.
