### Other changes

- Times Square now explicitly refuses to check notebooks from forks. Before creating or re-running GitHub check runs, the worker verifies that the repository's owner is in `TS_GITHUB_ORGS` and that the head commit is on a branch of the repository: either the head of a branch, or in the history of the branch it was pushed to or of the default branch. A fork's commits are on none of the repository's branches, while commits that arrived through a merged pull request from a fork, and commits in an installed repository that is itself a fork, are still checked. Previously, forks were excluded only as a side effect of GitHub sending `check_suite` webhook events solely for commits pushed to the repository where the app is installed.

  Commits that were pushed to the repository but are no longer on any of these branches are skipped too, since GitHub serves them just like a fork's commits. Examples are the head commit of a pull request whose branch was deleted after a squash or rebase merge, and a commit that was force-pushed away. Re-running a check on such a commit, or on a fork's commit, concludes it as cancelled, with a summary that names both possible causes. The conclusion is not neutral because GitHub counts a neutral check as passing for required status checks, so a refused re-run would otherwise turn an earlier failure into a pass.

  A check suite is requested seconds after a push, and for a moment GitHub may still show the branch as it was before the push, which looks like a commit that is not on the branch. So when a newly requested check suite's commit is not found, but its head branch is not found either or is at an ancestor of the commit, the worker defers the job and tries again up to three times over about 30 seconds before skipping it. A deferral does not post a Slack alert, and each deferral and the final outcome are logged with the attempt number. The commit is checked only if a later attempt finds it on a branch, so for a fork's commit this only delays the skip. Check suites with no head branch, rerequested check suites, and re-requested check runs are not retried, since GitHub lagging behind a push does not explain why their commits are missing.
