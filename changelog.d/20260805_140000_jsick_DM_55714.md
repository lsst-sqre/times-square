### Other changes

- The `GET /v1/pages/{page}/html/events` SSE stream no longer restates unchanged state once a second. A subscriber now receives one initial event reporting the page instance's current execution and rendering state (with null fields when nothing has happened yet), and after that an event only when that state changes. A terminal execution failure is reported once, and the server still never closes the stream, so a later re-execution is reported without resubscribing. Keep-alive is left to the SSE comment pings sent every 15 seconds.
- The events stream's polling now adapts to the page instance it is reporting on. While a notebook execution is in flight, or the state has just changed, the stream keeps polling once a second, so clients see changes as promptly as before. Once a subscription goes idle the interval doubles after each unchanged poll — 1, 2, 4, 8, then 10 seconds — and resets to one second as soon as an execution is queued or the state changes. An idle subscription therefore costs a fraction of the Redis lookups it used to, which matters most for the long-lived streams that dashboards leave open on settled pages.
