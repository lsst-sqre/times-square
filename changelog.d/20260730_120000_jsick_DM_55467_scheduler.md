### Bug fixes

- The run scheduler now treats a page whose stored recurrence rule set cannot be parsed or evaluated as a per-page configuration error rather than an internal error. Such a page is skipped, the remaining pages are scheduled as usual, and the problem is logged once per page per worker process at warning level (naming the page and the reason) instead of raising an error on every five-minute `schedule_runs` tick. Previously a single unusable schedule produced an error-level log — and a corresponding Sentry event — on every tick. Genuinely unexpected errors are still logged as errors.
