### New features

- Added a `times-square backfill-github-ids [--dry-run]` CLI command that fills in GitHub's stable numeric repository, owner, and app installation IDs on GitHub-backed pages that predate ID capture. It iterates the distinct owner/repository name pairs that have no repository ID recorded, resolves each one through the GitHub App API, and bulk-updates that repository's pages, so renames are handled by ID from the start rather than only after each repository's next sync. `--dry-run` resolves every repository and reports the pages it would fill in without writing anything, and pages that already carry a repository ID are never rewritten, so the command is safe to re-run. Repositories the GitHub App cannot resolve — deleted, made private, or renamed out from under the stored names — are logged with their owner and repository names and skipped without aborting the run; `rename-github-owner` remains the manual fallback for renames the App never sees. The command is intended to be run once per deployment as a Kubernetes job, which is documented in the new [Backfilling GitHub numeric IDs](https://times-square.lsst.io/user-guide/github-id-backfill.html) guide.
