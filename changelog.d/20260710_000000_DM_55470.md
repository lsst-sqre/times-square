### New features

- The `GET /v1/pages/{page}/htmlstatus` endpoint now returns a terminal execution-failure result instead of HTTP 500 when Noteburst reports that a notebook could not be executed. The `HtmlStatus` response gains a new optional `execution_error` object carrying a machine-readable `code` and a human-readable `title` and `message`. A cached failure short-circuits re-execution so a persistently broken notebook no longer triggers a fresh Noteburst execution on every poll. Deliberately requesting a new execution (updating the page or soft-deleting its HTML) clears the cached failure immediately, so a terminal result never masks a fixed notebook. An in-flight Noteburst execution likewise always takes precedence over a cached failure. This field is additive and backward compatible: it is null in the normal, pending, and available cases.
- How long a terminal execution failure stays cached — and therefore how long before a persistently failing notebook is retried automatically — is now configurable with the `TS_EXECUTION_FAILURE_LIFETIME` environment variable, which defaults to 600 seconds.
